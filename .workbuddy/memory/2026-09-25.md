## 第四轮：调参面板去掉持久化（2026-09-25 上午）
用户截图调参面板常驻页面。根因：`TopSearch.svelte` 的 onMount 里
`sessionStorage.getItem(TUNE_KEY) === "1"` 会恢复上次开关状态 —— 用户按过一次
Ctrl+Shift+E 后，面板每次刷新都自己出现。修法：删掉 TUNE_KEY 读写与常量，
每次打开页面都从关着开始，仅靠 Ctrl+Shift+E 切换。
探针验证（并预置 sessionStorage 种子确认旧值不再被读）：fresh=false →
按键=true → 再按=false，无 JS 错误，tsc/biome 干净。
教训：给"调试工具"做状态持久化是反模式 —— 调试 UI 应当永远默认关闭。

## 第三轮：文章面板「做成液态玻璃」（真因：显隐观察者把 nest 目标判出局）

### 症状
- 用户截图：ProMax 展开「文章」面板 = 一块 0.198 白底 + `blur(5px)` 的磨砂板，
  没有折射、没有棱线（原话「做成液态玻璃而且你看图片这是什么」）。
- 探针：`[data-ai-panel]` 展开后 `data-lg-on` **缺失**，`backdrop-filter: blur(5px)`
  （样式表那份）；`--lg-tint-bg` 是从**导航岛继承**来的 0.198（面板渐变里用的就是它）。

### 真因（`src/components/features/LiquidGlass.astro`）
1. 面板 SSR 就是 `visibility:hidden` → `applyGlass` 的可见性检查直接 return false →
   `run()` 给它挂 `watchReveal`（MutationObserver），等露头再上玻璃。
2. 露头时观察者回调 `if (!isReadyTarget(el)) return;`，而 `isReadyTarget` 里有
   `el.closest("[data-lg-on]")` —— **面板就长在已上玻璃的导航岛内部**，于是被自己的
   祖先判出局：观察者既不上玻璃也不自摘，面板永远停在白板。
   （PRESET 里 `.ai-float-island` 明明是 `nest: true`，但 isReadyTarget 没传 cfg 进来。）
3. 第二层坑：手动 `register()` 能上玻璃，但「展开→收起→再展开」会丢一次 ——
   收起时面板尺寸变化 → ResizeObserver → `rebuildNow()` → `revertGlass` + `applyGlass`，
   此刻面板已 `visibility:hidden` → 重上失败，而观察者上次成功后已自摘 → 没人再管。

### 修复（LiquidGlass.astro 三处）
- `isReadyTarget(el, cfg)`：`if (!(cfg && cfg.nest) && el.closest("[data-lg-on]")) return false;`
  （nest 目标允许住在玻璃里）；三个调用点全部传 cfg（⚠ 同一文件并行编辑会丢改动，逐个改完 grep 核对）。
- `applyGlass`：可见性失败时 `if (cfg.force) watchReveal(el, cfg);` —— 点名目标每次显形
  都要有玻璃，观察者自摘后必须重挂。
- 面板底色是**渐变**（`background-color` 恒为 transparent），所以引擎只给它折射、不写
  `background-color`；透底靠继承岛的 `--lg-tint-bg` → 与岛同材质，正是想要的效果。

### 顺手：用户截图里那枚大白「⌄」不是面板的东西
- 是首页壁纸全屏模式的 `#scroll-down-indicator`（向下滚动提示，
  `bottom:5rem; left:50%; z-index:10`）。ProMax 把岛沉底后它正好和岛/面板叠在一起，
  隔着半透玻璃透出来，看着像面板里凭空多了个箭头。
- `promax.css` 新增：`body.site-promax:has(.article-island.open) #scroll-down-indicator
  { opacity: 0; pointer-events: none; }`（面板开着时让位，收起自动回来）。

### 验证
- 七步断言（初始/展开/收起/再展开/切页/切页后展开/切页后收起）：三次展开全部
  `data-lg-on + url("#lg-17") brightness(1.04)`；岛全程 `url("#lg-1")` 没丢；
  展开时指示器 `opacity: 0`、收起恢复 `1`；无 JS 报错。
- normal / lite：面板仍不上玻璃（引擎被版本门挡着），无报错，行为未变。
- biome format、tsc --noEmit 干净；验收截图 `.workbuddy/artifacts/panel-glass-full.png`
  （放大件 `panel-glass-zoom.png`）。

### 坑（本轮新增）
- **探针必须先等 `document.readyState === "complete"` 再点**：dev server 的模块图很慢，
  `PREP_DELAY=4500` 时页面还停在 `interactive`，组件脚本的 DOMContentLoaded 回调没跑 →
  `[data-ai-trigger]` 上**一个监听都没有**（`getEventListeners(trig)` 返回 `{}`），
  `click()` 毫无反应。我因此白查了很久（一度怀疑 open() 被改坏）。
  prep 开头统一加：`for (let i=0;i<100 && document.readyState!=="complete";i++) await sleep(300);`
- 判断「引擎能不能玻璃化某元素」最快的三分法：探针里直接
  `window.__liquidGlass.register(panel, cfg)` —— 返回 true 且 `data-lg-on` 出现
  = 元素没问题，问题在**谁去调它**（观察者/扫描路径）。

### 坑（上一轮）
- **玻璃的内联值只属于引擎**：站在组件侧看，「把内联样式清干净」是很自然的复位写法，
  但 `background-color` / `backdrop-filter` 正是引擎的地盘。判据永远是
  `el.hasAttribute("data-lg-on")`；要抹就先抹再 `__liquidGlass.rebuild(el)`。

## 顶部搜索：把 `1.txt` 那份 iOS26 液态引擎整份搬过来（去掉黑条/壁纸/调参面板）

用户指令原文：「所有代码全搬过去 但是去掉黑条和壁纸和调参（调参用ctrl shift e)」。
参考实现 `E:\NanLuo321.github.io-main\1.txt`（iOS 26 QuartzCore `default.metallib`
反汇编复刻的 WebGL2 + SDF 玻璃）。移植落点：`src/utils/metaball-melt.ts`（新建，引擎）
+ `src/components/controls/TopSearch.svelte`（换成真引擎，删掉旧的 CSS+SVG goo 近似）。

### 根因：画布一片空白 —— 顶点着色器被我写歪了（本轮最大的坑）
移植时把全屏三角形写成了 `vec2((gl_VertexID<<1)&2, gl_VertexID&1)`，第二项应该是 `&2`：

| id | `(id<<1)&2` | `&1`（错） | `&2`（对） |
|---|---|---|---|
| 0 | 0 | (0,0) | (0,0) |
| 1 | 2 | (2,1) | (2,0) |
| 2 | 0 | (0,0) ← 与 id0 重合 | (0,2) |

→ 三角形**面积为零**，光栅化直接丢弃，`gl.drawArrays` 一个像素都不画，
而且 `gl.getError()` 恒为 0、上下文不丢、控制台无报错。修完立刻出图。
**教训：GLSL 里「不报错但什么都不画」优先怀疑顶点覆盖退化。**

### 排查这条路上两个浪费时间的假象
1. **`gl.readPixels` 读不到内容**（默认 `preserveDrawingBuffer:false`，且页面侧 rAF 与
   组件 rAF 谁先谁后不定）—— 同一位置一次 `3,4,6,251`、一次 `0,0,0,0`，
   连采 40 帧取最大也没救回来，被我误读成「shader 根本没画」。正解：截图 + 离线解 PNG。
2. **版本门 `#version-gate` 在 prep 等待期间才盖上**，截出一张全黑的图，
   差点被当成「改动把页面弄黑了」。prep 收尾要循环压几次。

### 「去掉黑条」的连带处理（都是量出来的，不是看出来的）
参考实现的黑条是 `uEdge=26` 的半平面。把它退到视口外只是第一步，
它还会留下两样东西，都实测到了：

1. **页面顶端一条全宽软阴影带**。`shade = exp(-(p.y-uEdge)/30)*0.26`，
   在纯灰 rig 上实测 y=0→alpha 0.31、y=26→0.11、y≈110 才消失，**逐点吻合模型**。
   黑条没了却留着它的影子。修法：阴影拆两份，`barVis = clamp(uEdge/26,0,1)`
   控制黑条那份，液滴自己那份用 `blob.x` 单独算（`max(shadeBar*barVis, shadeBlob)`）。
   液滴自带晕圈保持原样（实测 x=660/638/616/594 → 104/116/122/125，
   与 `exp(-blob.x/30)*0.26` 的 0.187/0.089/0.043/0.021 逐点吻合）。
2. **最顶一行一条 1px 全宽深色描边**：半平面下沿正好压在 y=0。
   修法：`meltTuning.edge` 从 `0` 改成 `-1`（下沿推出视口 1px），
   液颈几何不受影响。修完 `col 1200` 从 y=0 起全是 128。

   ⚠ `edge` 没暴露在调参面板里，但 `resetTune()` **遍历 `TUNE_DEFAULTS` 的全部键写回**，
   所以 `TopSearch.svelte` 里那份 `TUNE_DEFAULTS.edge` 必须同步改成 `-1`，
   否则一按「复位」描边就回来。

### 架构决定（沿用上一轮的结论）
canvas 的透明像素**不遮罩** `backdrop-filter`（整块都糊）→ 真折射只能由 DOM 层
`.ts-lens`（`border-radius` 裁剪 + `backdrop-filter`）承担，shader 只负责材质；
画布 `clearColor(0,0,0,0)` + `premultipliedAlpha:true` 让页面从底下透出。

## 第五轮：改动上传 GitHub（2026-09-25 上午）

用户要求「上传至 github」。目标仓库 NanLuo321/NanLuo321.github.io（public，默认 main）。

**关键状态**：本地 .git 是零提交的初始仓库（本目录是 GitHub 下载的 ZIP 解压而来），
远端却有完整历史（HEAD 333c614，另有 dependabot 分支与 PR）。直接 push 会非快进被拒，
强推会抹掉远端历史 —— 必须先把本地接驳到远端历史上再追加提交。

**接驳做法（全程不动工作区文件）**：
1. git remote add origin + git fetch origin main
2. git update-ref refs/heads/main <远端SHA>
3. git symbolic-ref HEAD refs/heads/main
4. git reset --mixed —— index 填充为远端树，工作区一个文件都不动；
   之后 git status 精确显示 29 项差异（15 改 + 14 新增），而不是把上千文件当新增。

**环境坑（下次直接用）**：
- **refs/remotes/** 的写入在本环境被静默丢弃**：git update-ref refs/remotes/origin/main <SHA>
  返回 0 但文件不存在（fetch 自带的 main -> origin/main 也没落盘）；refs/heads/** 完全正常。
  → 别依赖 origin/main，直接建本地 main。
- **HTTPS 走本地代理会断**：环境有 https_proxy=http://127.0.0.1:58904，git push 报
  schannel: server closed abruptly；git ls-remote 报 CONNECT tunnel failed, response 502；
  fetch 也只有 100KB/s 爬了 15 分钟。→ 改用 SSH：本机 ~/.ssh/id_rsa 已在 GitHub 注册，
  ssh -T git@github.com 认证通过，推送 2.88 MiB/s、35 秒完成。
  git remote set-url origin git@github.com:NanLuo321/NanLuo321.github.io.git

**结果**：提交 36de254「feat(search): 液态玻璃搜索与 ProMax 界面改版」，
402 文件 / 61.73 MiB，333c614..36de254 main -> main。远端历史完整保留。

git 记成 gitlink/submodule 引用（指向不存在的提交），别人 clone 会报错。用户虽选「全部传」，

## 左缘拉出时间显示（LeftTime.svelte）—— 与顶部搜索同一套液体管线

用户需求原文：「给我写一个向左拉出时间显示（苹果那种的时间拉伸）(跟向下拉出搜索框一样)」。
实现为「从左缘往右拖 → 液滴拉出 → 弹簧落定成时间面板」，把顶部搜索那套交互
（TopSearch：「从顶边往下拖 → 搜索胶囊」）原样转到屏幕左缘。

### ① 引擎：给 metaball-melt 加 `orient: "top" | "left"`
**关键取舍：不改 shader 的形状/材质公式，只在 fragment 入口把坐标系沿对角线翻一下**
```glsl
if (uOrient > 0.5) p = p.yx;   // vec2(gl_FragCoord.x, uRes.y - gl_FragCoord.y) 之后
```
于是「顶边半平面吸附、液颈、贴边黑玻璃、上黑下透的压暗、45° 双光高光」全部
原封不动变成左缘版本（pp.yx 是沿对角线的镜像，恰好把 +y 方向映射成 -x 方向）。
⚠ 配套：CPU 上传 uniform 时 blob / 液凸要**按同一套翻转**（`(cy,cx,bwy,bwx)`），
而 `uRes` 必须保持**屏幕尺寸**（y 翻转发生在翻转之前）。
轴向相关的 CPU 逻辑共 5 处，都按 orient 分支：`down()` 起始轴、drag 钳制轴、
`up()` 阈值轴（left 量 x 与视口宽）、`retract()` 目标轴、retract 完成判定轴
（left 看 `sp.bx`）。`up()` 签名由 `up(y)` 改成 `up(x, y)`，TopSearch 调用点同步改。

## 时间面板改版：「iOS 锁屏分量」+ 干掉"过渡"（2026-09-26 上午）
用户原话：「这为啥有个过度 而且我要的是这种（看图片 iPhone 锁定画面 時間拉長）」。

**"过渡"是什么 / 怎么修的**
- 现象：拖出时间面板后能看到「液态 blob ↔ DOM 面板」两层玻璃在同一格里各自淡入淡出，
  叠成「双重玻璃」+ 一道虚的二级小玻璃阴影（旧 box-shadow 60px blur 把那层糊出来了）。
- 修法（三处，都在 `LeftTime.svelte`）：
  1. `.lt-panel` **去掉 transform 过渡** —— 之前是 `translate(-16px,-50%) scale(0.98) → 0/-50%/1`
     over 500ms，液态 blob 收尾位置本来就在面板那一格，再 scale 飘一下就叠出"第二层"。
     现在默认就是 `translate(0,-50%) scale(1)`，零位移。
  2. 面板 opacity 淡入从 340ms 缩到 **120ms**，只用来盖住弹簧最后那两帧回弹；
     `showMelt` 淡出从 260ms 同步到 120ms —— **两者交叉淡入淡出窗口压到 120ms**。
  3. `onSettle` 里立刻 `showMelt(false); meltOn = false`，不再等 onPhase "idle" 才收画布。
  4. `box-shadow` 从 `0 26px 60px rgba(0,0,0,0.22)` 收紧到 `0 12px 28px rgba(0,0,0,0.16)`，
     底下不再有那道虚的二级小玻璃阴影。

**iOS 锁屏分量**
- 面板尺寸：380×246 → **360×320**（高度优先，时间是主角、日期压下面）。
- 时间字号：clamp(64px,7.6vw,96px) → **clamp(72px,10.5vw,132px)**，占满面板宽。
- 删了「秒 / 本地时间 / 呼吸点」三样配角，只留 `07:48`（大号）+ `星期六 · 9月26日`（小号）两行。
- `letter-spacing: -0.04em` + `tabular-nums` + `font-weight: 700`，与 iOS 锁屏 font-stack 同感觉。

**验证**
- 无头整屏截图（避免裁剪漏看）：`.workbuddy/artifacts/lt-open.png` 显示面板单一一块玻璃、无 halo、无第二层；
  时间 `07:51` 与系统时间一致，日期正确。
- biome + tsc 干净。

## 时间面板改版三：「板块别删 + 一颗进壁纸的独立按钮」（2026-09-26）
用户原话：「我的意思是板块别删 加个进壁纸的单独按钮然后用LiquidGlass的时间 拉伸长方形时间
角色坐标你看着搞」——**否定了上一版彻底删掉玻璃盒的做法**：玻璃盒（板块）要留着，融进壁纸
改成**另一形态**，由一个独立按钮切换。

### 设计：一个 DOM、两种形态、同一个 LiquidGlass
`.lt-panel` 上多一个 `class:wallpaper={wm}`，其余全部共用（同一套折射预设）：
| | 板块（默认） | 进壁纸 |
|---|---|---|
| 尺寸 | `min(460px,76vw) × 248`，radius 34 | `min(760px,86vw) × 176`，radius 46 |
| 位置 | `vw/2, vh/2`（CSS `top:50%`） | JS 写内联 `top` = 角色代理锚点 |
| `background-color` | `rgba(255,255,255,.42)` | `rgba(255,255,255,.10)` |
| 落定动画 | `ltTimeStretch` scaleY 1.45→1 | `ltTimeStretchWide` scaleY 1.5→1 **+ scaleX 0.94→1** |

- **底色必须走纯 `background-color`，不能用渐变**：LiquidGlass 的透底（tint）只认
  `background-color`，渐变底读不出 alpha → `__lgNeedTint` 永远等不到基准，折射被实底盖死。
  玻璃表面的光泽改用 `.lt-panel::before` 那层低 alpha 斜向渐变（压在折射之上也不遮背景）。
- **形态切换必须让透底基准作废**：引擎把 `__lgBaseBg` 只记一次（`baseBgOf`）。从 0.42 切到 0.10
  就停在旧底色上。切形态时走 `rebuildPanelGlass()`：清 `el.__lgBaseBg` → `unregister` →
  `requestAnimationFrame` → `register(el, PANEL_LG_CFG)`。实测 0.42→`alpha 0.1888`，
  0.10→`alpha 0.0458`（= ×0.62 tint ×0.72 promax），**基准确实重记了**。
- **独立按钮 `.lt-mode` 钉在面板右上角里面，不做「吊在下沿外边」**：进壁纸形态的面板底边
  已经贴到沉底导航岛上沿（面板中心上限 `vh-196`），再往外挂东西必然压岛。
  实测 `btnRect.bottom=569 < vh-80=728` ✓。
  它住在已上玻璃的 `.lt-panel` 内部 → LiquidGlass 预设**必须 `nest: true`**（否则被
  「玻璃上不再叠玻璃」拒掉），且 `tint: 1`（深底白字，透底会读不出来）。
- **角色代理锚点收紧**：`cy = min(vh-196, heroOverlay.bottom + 140)`（原 +200/vh-180）。
  vh=808 时锚点 612，面板落在 524~700：上不压 hero 文字（bottom 495）、下离岛 28px。
  无覆盖层时退 `min(vh-196, vh*0.66)`。
- `wm` 存 `localStorage.ltWallpaperMode`，重进站记住上次形态。
- 对外 API 多两个：`window.__leftTime.wallpaper(on)` / `.mode()`（探针与调试用）。

## 壁纸角色凸出：时间在角色后、但不在壁纸后（2026-09-26）
用户原话：「主页的API壁纸能不能加个选项在下方的岛里 加个自定义选项 然后读取壁纸角色 角色凸出

### 三层景深（核心）
| z | 元素 | 内容 |
|---|---|---|
| -1 | `#wallpaper-wrapper` | 壁纸原图 |
| 65 | `#left-time` | 时间 |
| 66 | `#wallpaper-subject` | **同一张壁纸再画一遍** + `mask-image` 只留角色 → 角色压住时间 |
| 80 | `#top-row` / `#mobile-nav-island` | 原 z 提到 80，免得角色盖住导航岛 |

角色层不是「抠出来的 PNG」，是原壁纸 + 蒙版：**不抠图、不建模型、不联网**，几何跟原图逐像素
对齐（`object-fit: cover` 的 `contentRect` / `mapBoxToViewport` 复刻）。
蒙版算法 `src/utils/wallpaper-depth.ts`（纯 canvas）：缩 192px → 背景边框建模 → 显著性
（色差 .44 + Sobel .22 + 居中 .14 + 彩度 .20）→ `boxBlur(sal,1)` → Otsu（夹 40..220）→ 开1
→ 闭2×8邻域 → 最大连通域（居中加权）→ 内部孔洞洪填 → 外接框 + 羽化 2.4px → 白+alpha PNG。
三张真图实测 25~223ms、占比 40/52/55%。

### 面板与「不能删 API」
`Navbar.astro` 加 `#wp-source-toggle`；`WallpaperDepth.astro` 出 `#wp-depth-panel`（来源分段
API/自定义 + 深度开关 + 状态行 + 重新识别 + 选文件/清空/贴地址）。切回 `api` 时把 img 还原成
`data-wpOrig`（实测 `matchesOrig:true`、src 回 `https://t.alcy.cc/ycy`）；`backgroundWallpaper.ts`
一字未动。

### CORS 铁律（API 图为什么凸不出来）
`t.alcy.cc` 无 `Access-Control-Allow-Origin` → canvas 读不到像素，纯前端无解；试过的代理全废
（wsrv.nl 拉黑 `.cc`、allorigins 26s、codetabs 挂）。所以 API 图只能「凸出」不能自动识别，面板
给明确提示；要真凸出必须用可读图（同源/blob/自选）。加了 URL 级负缓存 `unreadableUrls`，
避免「重新识别 / 来回切来源」反复刷 CORS 报错。

### 修掉的并发 Bug（本轮真发现的问题）
`analyze()` 里 `mask = m` 之后还有 `await dataUrlToBlobUrl()` 才 `paintSubject()`，而
`paintSubject()` 不看 `state.depth` → 识别到一半关深度/换壁纸时，迟到的一轮会把**上一张图的
角色蒙版糊到新图上**；且早先的 `if (busy) return` 会让「换来源后不重新识别」。
修法：`analyzeGen` 世代号（每个 await 后核对，对不上整轮作废）+ `setImgSrc()`/`resetMask()` 里
`analyzeGen++` + `paintSubject()` 首行 `if (!state.depth) return`；并改成**先画层、后置 `mask`**，
使 `hasMask===true` 必定意味着角色层已贴好。

z 序 `time:65 < subject:66 < island:80`；三张真图 `subjectOn/subImg=true`、tone=ok；
`midAnalysisAbort.ok=true`（识别中途关深度不再画回来）；时间嵌进角色：角色框中心 422、

## 壁纸角色「只压时间」：z 分层 + 按时间框裁一刀（2026-09-26）
用户原话：「文字不要覆盖 我只要覆盖时间 包括上方的搜索框 向下翻的时候壁纸角色给我文章挡住了」。

### 问题定性
角色层（`#wallpaper-subject`，壁纸的第二遍绘制）原来 z:66 —— 糊在正文(30)/搜索(65) 上面。
但**光靠 z-index 保不住「文字」**：横幅标题 `.banner-title` 挂在 `#banner-overlay-container`(z:20) 里，
而那个容器关在 `#wallpaper-wrapper` 的 **z:-1 负层栈**里出不来 → 任何比 -1 高的层都能盖住它。

### 解法（两件套）
1. **z 分层**（`WallpaperDepth.astro` 的 is:global）：
   | 层 | z |
   |---|---|
   | `#wallpaper-subject` | 25（默认，在正文 30 之下）；`body.wp-subject-armed` 时 → **62** |
   | `#left-time`（进壁纸形态） | **58**（>正文 30 / #content-wrapper 50；<搜索 65） |
   | 顶部搜索 65 / 导航岛 80 | 不动 |
2. **按时间框裁一刀**：`applySubjectClip()` 把角色层 `clip-path: inset(...)` 到
   `.lt-panel.show.wallpaper` 的外接框 + `CLIP_PAD=14`（时钟 text-shadow 外溢 ~20px）。
   框外连像素都没有 → 标题/文章/搜索全露出来，时间照样被角色压着。
   - 裁切的**前提**：角色层跟壁纸亮度必须完全一致，否则边界露亮缝。角色层挂在 wrapper 外，
     吃不到那层 `rgba(0,0,0,0.2)` 暗化 → 亮 25%。所以配 `syncSubjectTint()`：把
     `.banner-dim-overlay` 的 background-color + `#wallpaper-gradient` 的 background-image
     镜像到角色层里那层 `.wp-subject-tint`，**且必须给它套上和 img 同一张 mask**
     （不套 → 整个裁切框被压暗 20%，框内出现暗方块）。

### 踩到的坑（都值得记）
1. **`analyze()` 的顺序**：`paintSubject()` 跑在 `mask = m` **之前**，所以裁切判定不能依赖 `mask`
   → `clipNeeded()` 只看**几何/形态**（promax + lt-in-wallpaper），能不能抬层由
   `applySubjectClip()` 同步的 `body.wp-subject-armed` 决定。否则深度「关→开」后裁切不回来。
2. **滚动会让壁纸变模糊**：全屏模式给壁纸 img 挂了 `filter: blur(var(--scroll-blur)) !important`。
   角色层是第二遍绘制，必须 `syncSubjectLook()` 实时镜像 filter/opacity，否则一往下滚
   角色还清的、边界穿帮。用 capture 阶段 scroll 监听（60ms 节流）。
3. **时间不能沉到正文之下**：早前把进壁纸的 `#left-time` 沉到 z:20，结果向下翻时一张玻璃卡
   正好停在时间那格把它盖了 → 改成 58。

## 时间「看得见」三件套：自动避让 + 可拖动 + 右上角 X（2026-09-26）
用户原话（配两张截图）：「角色突出时间就露出一点 你想办法能看见并且右上角加个X 点击空白处时间不关闭」
+「回板块这区域变成可拖动的」。确认稿（AskUserQuestion）：时间=**自动避让+可拖动**（保住景深，
拖到空处就全露）；拖拽热点=**整个面板都能拖**。

### 为什么「时间只露一点」是机制内生的
角色层 = **同一张壁纸再画一遍 + mask**，与壁纸逐像素一致（亮度也对齐了）→ 它**唯一看得见的作用
就是遮挡**。所以「角色盖住时间」这件事没有参数可调，只能改**时间待在哪儿**。

### 三件套实现
1. **自动避让** `bestSpot(w,h)`（`WallpaperDepth.astro`）：把 mask 画进 96×N canvas 得
   alpha 地形图（`buildMaskGrid`）→ 候选 9×7 个落点，`gridCoverage()` 量面板矩形里的平均厚度
   → 取最薄的一个。`object-fit: cover` 的归一化反算由 `maskMapper()` 复刻。
   对外 `__wallpaperDepth.bestSpot`；`LeftTime.refreshAutoPos()` 在**开面板 / 切形态 /
   识别完(wallpaperdepthchange)** 三处重算，`spot = 用户拖过的 pos ?? autoPos`。
2. **整个面板可拖**（`LeftTime.svelte`）：`onPanelDown`（按钮上按下放行）→ 4px 阈值 →
   `clampPos` 夹在视口内；拖动中 rAF 节流 `publishMode()` 让那一刀立刻跟手；松手 `storePos`
   落 `localStorage.ltPanelPos`（**按形态分开存**）；**双击 → 清 pos 回自动避让**。
3. **右上角 X + 点空白不关闭**：`.lt-tools`（absolute top12/right14）里放 `.lt-mode`(回板块) +
   `.lt-x`；**删掉**原来「pointerdown 在面板外 → 关闭」那条监听，只留 Esc / X。

### 这轮修掉的两个真 bug（都是探针逼出来的）
1. **`clipSafe()` 的「有别的元素就算不安全」是错的** —— 顶部搜索的抓取条
   `button.ts-grab`（`top:0;height:26;left:0;right:0;pointer-events:auto`）跟时间框的角**天天重叠**，
   于是整页顶部被判成正文 → `armed=false` → **那一刀永远不裁，景深全灭**。
   改成只认**正文容器**：`CONTENT_SEL = "#main-grid, #content-wrapper, #swup-container, .footer"`
   （`elementsFromPoint` 带祖先，`el.closest(CONTENT_SEL)` 一路向上找即可）。
   ⚠ 悬浮控件（搜索/岛）本来就在角色之上(65/80)，**不该参与**这个判定。
2. **滚动不重算那一刀**：scroll 监听原来只 `syncSubjectLook()` —— 在顶部 armed(62) 的角色
   往下一滚压到文章卡片上，会一直糊着卡片，直到下次别的什么事件才纠正（探针当时是靠
   裁切泵还在跑才"侥幸"通过）。给 scroll 监听补上 `applySubjectClip()`。

### 顺带收紧的落点约束（软罚分 → 硬约束）
`bestSpot` 原来给「顶部搜索带(y<108) / 沉底导航岛(vh-104)」各记 **+0.06 罚分**。

## 玻璃时钟 + 拉长（Phase D，同日接续）

用户给了一张 macOS Big Sur 风格的磨砂玻璃细长数字钟截图：**「能不能做成这种玻璃然后拉长」**。
追问两题后确定：玻璃对象 = **两者都要**（玻璃数字 + 下面一层很淡的玻璃托底）；
拉长 = **常驻细长**（不是只在落定动画里拉一下）。改动集中在 `src/components/controls/LeftTime.svelte`。

### ① 玻璃数字（`.lt-panel.wallpaper .lt-hm`）
- 手段：白色渐变裁进字面 —— `background-image: linear-gradient(...)` +
  `-webkit-background-clip: text` / `background-clip: text` +
  `-webkit-text-fill-color: transparent`，字身带 alpha，所以壁纸从字里透出来；
  再加 `-webkit-text-stroke` 当玻璃棱角高光。
- **暗描只能用 `text-shadow`，不能用 `filter: drop-shadow`**：`background-clip:text`
  与 `filter` 撞在同一个元素上时，Chromium 会把这一格**整个画成空白**
  （computed style 全对、像素上什么都没有）。第一版就是被这条坑到，看着像「字变虚」，其实整块没画。
  取证方式：lab 页里同一条渐变逐行对照（纯渐变 / 加 stroke / 加 filter / 加 transform），
  量 p99：纯渐变那行 p99=239/max=243（渐变确实画了），加 filter 那行掉回背景值。
- 字重 700→400：300 + 透明字身 + 暗描，在中灰底上只剩「描边」观感，落到亮壁纸更糊。
  400 是「细」与「读得清」的分界。

### ② 常驻细长（`.lt-panel.wallpaper .lt-hm { transform: scaleY(...) }`）
**⚠ `transform` 只改视觉、不改行盒** → 面板高度必须跟着涨
（`WP_H` 176→**232**，CSS 与 JS 同口径），否则拉出来的高字会顶到日期、甚至溢出面板。

### ③ 玻璃托底 `.lt-plate`（真折射那一层）
- **必须是 `.lt-panel` 的兄弟，绝不能是子元素**：`.lt-panel` 自带
  `transform: translate(-50%,-50%)`，而 transform 会给后代立一个 **backdrop root** ——
  子孙的 `backdrop-filter` 只能在面板内部取样、摸不到壁纸，折射当场失效。
  所以托底挂在 `#left-time` 下、**排在 `.lt-panel` 前面**（DOM 顺序 = 画在面板之下），
  几何由 JS 按面板 rect 内缩算，无 transform，用 left/top/width/height 定位。
- 折射走 LiquidGlass 引擎（`register(el, cfg)` → `data-lg-on`）。
  底色**刻意恒定不过渡**（`background-color: rgba(255,255,255,0.07)`）→ 满足引擎准入
  `hasGlassBackdrop()` 的 alpha≥0.04，register 一次就成，省掉面板那套 14×90ms 重试。
  显隐一律走外层 `opacity`。

### ④ 踩的三连坑（都靠探针/差分抓到）
1. **托底几何量在动画中间**：`.lt-panel.wallpaper.show` 挂着一记 0.7s 的 `ltTimeStretchWide`
   （scaleY 1.5→1、scaleX .94→1）。原来的「500ms 再量一拍」正好撞在**动画进度 0.65** 处 ——
   反推：托底 w692/h241 ⇒ 当时面板 744/273；由 w 推 p=0.649、由 h 推 p=0.647，两条独立推算都落在 454ms。
   量到的是**被 scale 放大过**的 rect，托底按旧值内缩就探出面板上沿 14px，且此后没人再纠正。
   → 改成**动画窗口内逐帧重排**（rAF，900ms 上限）+ 面板 `animationend` 收尾。
2. **`#banner-overlay-container` 混进了满屏容器**：它是 `#wallpaper-wrapper` 的满屏 flex 容器
   （背景全透明，只负责摆位），rect = 整个视口。拿它当「文字」用 → **每个**候选都判相交 →
   避让那一档**永远空转**，恒定回落成软罚分（现象酷似「罚分不够狠」，其实是判据被污染）。
   → 只收真正承载字的元素（标题 / 副标题），再加「覆盖 ≥92% 视口的不算文字」兜底。
3. **polygon 漏了一个角**：挖口多边形的右下角点漏掉后，`clip-path: polygon(...)`
   直接连回第一个挖口 → 右沿变成斜线、右上一角被白白切掉。探针「时间框整块露出来」当场抓到。

### ⑤ 「这一刀会糊掉横幅标题」——从躲开改成抠掉
**躲不开**（1416×808 实测，两条独立证明）：面板顶被搜索带硬约束钉死在 ≥118 → 框底最小 **364**；
标题行盒 335..425 → **最少也得交叠 29px**；横向绕开要面板中心 ≥1609，而 `bestSpot` 只有 1012。

那 29px 是**真损伤，不是抖动**（角色层开/关两张图作差，先跑两遍同脚本取噪声基线）：

| 区域 | mean\|dL\| | max | >12 的像素 |
|---|---|---|---|
